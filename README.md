# Taxpayer Behavioral Analytics

ASP.NET Core 10 system that tracks taxpayer behaviour on 4 SMS-driven landing
pages and stores everything in SQL Server. Single-process: the landing portal
also exposes the tracking API, so there's no cross-origin problem and you only
have one app to run.

## Solution layout

```
src/
  SharedLibrary/        EF Core entities, DTOs, security primitives (token, cipher, bot detector, UA parser),
                        and the SQL schema initializer.
  LandingPortal/        ASP.NET Core MVC app: serves the 4 Razor views, hosts the tracking API
                        (/api/v1/session, /api/v1/events/*), runs the background event flush.
db/
  schema.sql            SQL Server DDL for all 4 tables, indexes, and seed campaigns.
  partitioning.sql      Optional monthly partitioning for EventLog.
```

## SMS link format

```
https://iris.fbr.gov.pk/c?t=<22 char opaque token>     ~ 50 chars
```

The token is 16 cryptographically random bytes encoded as URL-safe base64
(22 characters). It's stored on `TaxpayerRecipient.TrackingToken` (unique index)
and reveals nothing on its own — only the server can resolve it to a recipient,
and the recipient row holds the NTN encrypted at rest via `PiiCipher` (AES-256-GCM).

With a 50-char URL you get ~110 chars of SMS body within the 160-char single-SMS
budget.

## Flow

1. Your existing SMS pipeline inserts a `TaxpayerRecipient` row with the
   encrypted NTN/mobile and a `TrackingToken` generated by
   `ITrackingTokenService.Issue()`.
2. SMS sent with `https://<host>/c?t=<token>`.
3. `CampaignController` looks up the token in `TaxpayerRecipient`, picks the
   Razor view named after `CampaignMaster.PageTemplate`
   (`Index | Enforcement | Combined | CivicDuty`), and renders it.
4. Embedded `tracking.js` calls **same-origin** `POST /api/v1/session/start`,
   then batches behavioural events to `POST /api/v1/events/batch` and pings
   `POST /api/v1/events/heartbeat` every 10s.
5. `EventFlushService` drains the in-memory queue into SQL Server in batches
   of up to 500 events with a 2-second ceiling.
6. The two CTA buttons go through `/c/redirect?t=...&target=register|file` so
   the click is recorded server-side before bouncing to IRIS.

## Tracked events

| EventType (int)  | Source | Notes |
| --- | --- | --- |
| `PageOpen` (1)        | `/api/v1/session/start` | One per session, includes IP, geo, browser, OS, device, screen, language |
| `PageClose` (2)       | `pagehide` / `beforeunload` | Beacon flush |
| `Heartbeat` (3)       | Every 10s while visible | Updates `DurationSeconds`, `MaxScrollDepth`, `VideoWatchSeconds` |
| `ScrollDepth` (4)     | 25/50/75/100 thresholds | Bounded event volume |
| `VideoPlay/Pause/Complete/Progress` (10–13) | `<video data-tptrack="video">` | `Progress` fires every 5s; `Complete` flips `IsBounce=false` and sets `VideoWatchPercent=100` |
| `RegisterClick` (20)  | `data-tptrack-cta="register"` | Beacon-flushed before redirect |
| `FileClick` (21)      | `data-tptrack-cta="file"` | Beacon-flushed before redirect |
| `CtaClick` (22)       | Any other `data-tptrack-cta` | |
| `OutboundRedirect` (23) | Server-side at `/c/redirect` | Tagged with `ref=` + `rid=` |
| `Engagement` (50)     | Derived: duration ≥ 15s OR scroll ≥ 50% | `UserSession.IsEngaged` |
| `BotDetected` (99)    | Server-side in `SessionController` | Session marked `IsBot`; future events dropped |

Aggregates live on `UserSession`: `DurationSeconds`, `MaxScrollDepth`,
`VideoWatchSeconds`, `VideoWatchPercent`, `RegisterClicked`, `FileClicked`,
`IsBounce`, `IsEngaged`.

## How to run

```bash
cd src
dotnet run --project LandingPortal
```

That's it — one process. On first start:

  1. Connects to `master`, runs `CREATE DATABASE TaxpayerAnalytics` if missing.
  2. Executes `db/schema.sql` (idempotent — every CREATE is guarded).
  3. Seeds the 4 campaigns (`GENERAL`, `ENFORCEMENT`, `COMBINED`, `CIVIC`).
  4. Hosts:
      - `/` and `/dev/test` — test launcher with dummy NTNs (Dev only)
      - `/c?t=<token>` — the actual landing page
      - `/c/redirect?t=...&target=register|file` — tracked outbound
      - `/api/v1/session/start`, `/api/v1/events/batch`, `/api/v1/events/heartbeat`
      - `/health` — liveness probe

Open `https://localhost:5001/` (Dev) and click into any of the 4 cards. Each
card shows the URL length so you can verify it fits in a single SMS.

## Verifying tracking

Watch the console:
```
info: Session 4b6f... started recipient=1 campaign=1 bot=False browser=Chrome device=Desktop
info: HTTP POST /api/v1/session/start responded 200 in 42ms
info: HTTP POST /api/v1/events/batch responded 200 in 8ms
```

Query SQL Server:
```sql
SELECT TOP 20 SessionId, CampaignId, RecipientId, Browser, OperatingSystem,
              DeviceType, DurationSeconds, MaxScrollDepth, VideoWatchSeconds,
              RegisterClicked, FileClicked, StartedAt, LastHeartbeatAt
FROM dbo.UserSession ORDER BY StartedAt DESC;

SELECT TOP 100 EventTime, EventType, EventValue, DurationSeconds, ScrollDepth, PageUrl
FROM dbo.EventLog ORDER BY EventTime DESC;
```

## Configuration

| Key | Purpose |
| --- | --- |
| `ConnectionStrings:AnalyticsDb` | SQL Server connection string (`(localdb)\MSSQLLocalDB` works for local dev) |
| `Security:NtnHashPepper` | HMAC pepper for `NtnHash` lookups |
| `Security:PiiEncryptionKey` | AES key for column-level NTN/Mobile encryption |
| `Security:RateLimitPerMinute` | Per-IP throttle on the tracking endpoints |
| `GeoIp:Enabled` / `GeoIp:DbPath` | Optional MaxMind GeoIP2 City DB |
| `Database:AutoApplySchema` | Disable to let a DBA manage schema in prod |
| `TestMode:Enabled` | Force-enable the `/` and `/dev/test` launcher outside Development |

## Security posture

- **No NTN in URLs.** SMS link contains only an opaque 22-char random token.
- **PII encrypted at rest.** `NtnEncrypted` / `MobileEncrypted` use AES-256-GCM.
- **NTN lookup without decryption** via deterministic `HMAC(NTN, pepper)`.
- **CSP, HSTS, X-Frame-Options, X-Content-Type-Options** on every response.
- **Bot filter** drops fake traffic before it pollutes analytics.
- **Per-IP rate limiting** (default 240 req/min, configurable).
- **HTTPS-only** redirection + `Strict-Transport-Security`.
